# Large File Split/Refactor TODO

This document tracks splitting the repository's 10 largest source files down to
under ~800 lines each. It was generated by analyzing the top-10 files by line
count (see `./scripts/ci.sh --static-only`-style tooling / the `top-large-files`
skill) and dispatching one analysis pass per file.

## Ground rules

- **Process files one at a time, in the order listed below.** Do not start file
  N+1 until file N's split is committed and `./scripts/ci.sh` (or the relevant
  subset — native/managed/Android build+test) is green.
- **Target: every resulting file under 800 lines.** Most proposed splits land
  well under that (200–550 lines is typical); a few line-count estimates below
  are approximate and may need one more split once the move is done for real.
- **No behavior changes.** These are pure move/reorganize refactors — same
  types, same members, same signatures, same namespaces/packages. Don't fix
  bugs, rename things, or "clean up while you're in there" in the same commit;
  file that as separate follow-up work.
- **Commit incrementally within each file's split**, following the suggested
  extraction order below (smallest/safest pieces first), verifying the build
  and relevant tests pass after each step — not just once at the end.
- Per `CLAUDE.md`, commits land directly on `master` prefixed `RMA-<n>:` — file
  or ask for a ticket number before starting if one doesn't already exist for
  this cleanup.
- Where a file has framework-specific mechanics (Unity `.meta` files, C#
  `partial class`, Android package visibility, Python sibling-file loading),
  follow the guidance in that file's section — they are not interchangeable.
